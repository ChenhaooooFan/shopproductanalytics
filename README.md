# NailVesta 链接数据深度分析

TikTok Shop 运营数据（product analysis list 每日导出）+ 达人组数据（Creators / Products / Videos / LIVE）的深度分析工具。

## 部署到 Streamlit Community Cloud

1. 这个仓库直接 Deploy，Main file 填 `nailvesta_link_analytics_app.py`。**`.streamlit/config.toml` 这个文件也要一起上传**（配色主题在里面，是 GitHub 默认不显示但会上传的隐藏文件，直接拖进网页上传框，或者用 git 推的话本来就会带上）。
2. **部署后必须做**：App 右下角 ⋮ → **Settings → Secrets**，粘贴下面这段，把 `xxx` 换成真实值（**只有你自己能看到这个 Secrets 页面，不会进代码仓库、不会给访问者看到**）：

   ```toml
   LARK_HOST = "Lark 国际版 (larksuite.com)"
   LARK_BASE_URL = "https://qusjdzq12vah.sg.larksuite.com/base/XwZwbY0NTairFWsejC3lr0zjg0t"
   LARK_APP_ID = "xxx"
   LARK_APP_SECRET = "xxx"
   ```

   达人组数据跟运营数据是同一个租户，同一份 App ID/Secret 会自动沿用，不用重复填 `CREATOR_APP_ID`/`CREATOR_APP_SECRET`。

3. 打开 App 就会自动去飞书检查、载入运营日报和达人组数据（不用点按钮）。第一次要把所有文件下载、识别一遍，之后只补新增的。侧边栏「① 测试连接」可以检查凭证。

## 🐱 问问小猫（问答功能，2026-09-27 新增）

每一页右下角有个小猫头，点它会弹出对话框，可以像跟 Claude 聊天一样用大白话问数据，比如「上周曝光为什么掉了」「DreamWear 8/24 改完有没有用」「哪个达人拖累最多」。小猫会先判断要用程序里的哪个分析（两段对比、异常预警、链接下钻、走势、大跌回暖、改动效果、链接排行、达人 / 内容排行、达人 Excel 字段环比），在程序内部真的跑一遍，再按「曝光优先、IM 单位、写清跟哪段比」的规矩回答。能连续追问；侧边栏开关在「运营」就问运营数据，在「达人」就问达人数据。

**要先配两样东西**（Streamlit Cloud：App 右下角 ⋮ → Settings → Secrets，跟 Lark 凭证写在一起）：

```toml
ANTHROPIC_API_KEY = "sk-ant-…"          # console.anthropic.com → API Keys 创建，按量付费
NV_CHAT_PASSWORD = "你自己定的口令"       # 公开链接上防止别人用你的额度
```

- 本地电脑上可以直接在小猫对话框里填，会存进本地 `.streamlit/secrets.toml`；公开部署上**不提供**在对话框里填（免得访问者替你设口令），只能去 Secrets 配。
- 模型：Claude Sonnet 5。一个问题通常查 2–4 次数据，每问约 $0.05–0.12，每个回答下面会显示这题大概花了多少。
- 防误刷：每个浏览器会话最多问 60 题、每题最多查 8 轮；对话只带最近 10 问的上下文。建议在 console.anthropic.com 给这个 key 设每月花费上限。
- `requirements.txt` 里多了 `anthropic`，部署时会自动装。

## 已知限制（公开部署 vs 本地跑的区别）

- **增量载入（2026-09-28）**：每个文件只下载、识别一次，识别结果存在服务器磁盘上；之后每次打开 App 自动去飞书对一遍附件清单，只下载、识别新增或被重新上传的文件，删掉的文件自动不再用。运营日报 186 个文件：第一次约 30 秒识别，之后打开约 1.5 秒；多 1 个文件也是 1.5 秒左右。侧边栏会写「新识别 X 个，其余直接用已识别结果」。「拉取（只补新增）」按钮保留，想立刻重新检查时点它。
- **内存（2026-09-28）**：达人组附件到 451 个（6 月逐日数据补进来后）时，旧版会把达人数据在内存里存三份（下载缓存一份、会话一份、页面整理时再一份，约 1.8GB），超过 Streamlit Cloud 的内存上限就会整个崩成「Oh no. Error running app」。新版只留整理后的一份：去掉没用到的长文本列（视频链接、来源文件名），日期存成真正的日期，重复的标题 / 发布时间只存一份，原始表整理完就释放——达人数据常驻内存从约 1.8GB 降到约 0.6GB，所有数字跟原来逐列核对一致。附件下载改成 6 个一起下（Lark 单个附件要 3–6 秒），第一次全量下载快 6 倍左右。
- **容器重启后会从零来一遍**：Streamlit Cloud 的磁盘不是永久的，App 长时间没人访问会休眠，醒来或 Reboot 后已下载、已识别的结果都没了，第一次打开要全部重新下载、识别（6 个附件一起下：运营日报 1–2 分钟；达人组 450 多个附件约 5 分钟），之后又恢复增量。本地电脑上跑不会有这个问题。
- **App Secret 安全**：侧边栏的 App ID / App Secret 输入框现在**故意留空**，哪怕 Secrets 里配置好了也不会回显——因为 Streamlit 的密码框只是界面上显示圆点，真实值还是会发到浏览器，公开给别人访问的话谁都能在控制台里看到。现在这样改了之后，配置好 Secrets 就会在服务器这边悄悄生效，输入框全程看不到任何真实值。

## 页面结构（2026-09-24 改版：曝光是索引列 + 结论先行）

侧边栏**最上面是「运营 / 达人」开关**，下面是同一套页面——开关切的是数据源，不是页面。

**判断口径：曝光（impression）是索引列。** 整个程序（运营 + 达人）判断「有没有异常」「表现好不好」都先看曝光，再看点击、CTR、CTOR、订单、GMV——GMV 涨了但曝光在掉，一样会被标出来。单位统一：曝光 = **IM**，金额 = **$**，点击 = 次，订单 = 单；比率的变化写「个百分点」。

**每一页同一个版式**：顶部标题栏（数据范围、对比的是哪两段）→ 一排状态胶囊（红 = 跌 / 绿 = 涨 / 灰 = 基本没动）→ 标签页，第一个标签永远是「结论」：红黄绿卡片，每句话都是大白话，写清楚「哪个指标、跟哪段日期比、现在多少、少了多少、降了百分之几」。其余标签是全指标归因 / 图表 / 明细表。

- **总览**：最近 7 天 vs 前 7 天（曝光 / CTR / CTOR / GMV）+ 最新一天有几条预警 + 下一步看哪页
- **深度分析**：两段对比·归因（每条链接的曝光 → 点击 → CTR → CTOR → 订单 → GMV 全指标归因）／多粒度对比／前端指标／后端指标
- **监控与溯源**
  - **异常预警**：每天扫所有层级（大盘 / 渠道 / 每条链接 / 每个达人）× 所有指标（曝光、点击、CTR、CTOR、订单、GMV），跟前 7 天中位数比，按曝光优先排序；点开一条就能看到这个对象当天的全部指标和原因
  - **链接下钻**：任一条链接最近 7 天 vs 前 7 天、掉在哪个渠道、近 14 天预警、改动记录；达人版多一个「达人与内容」标签（按挂车曝光排）
  - **日环比 & 回暖**：每天 vs 前一天；每次大跌之后有没有回到跌前（基线 = 跌前 7 天中位数）
  - **改动效果溯源**：改后 7 天日均 vs 改前 7 天日均，**先看曝光**：曝光涨 ≥10% 且成交跟上 = ✅ 有效；曝光掉 ≥10% = ❌ 变差；一涨一跌 = 🟡
- **参考**：指标归档
- **达人独有**（只在切到「达人」时出现）：达人 / 内容排行——默认按曝光排；本期 vs 基期、谁拉动谁拖累、每个达人 / 每条内容的全指标对比、集中度、新起量 / 掉线

**达人版「多粒度对比」= 四个 Excel 的每一个字段**：对比方式选 逐日 / 逐周 / 逐月 / 自选区间——
- 逐日 / 逐周 / 逐月：选一期，自动跟它的上一期比；Creators / Products / Videos / LIVE 各一个标签页，每个字段一行（上一期 / 本期 / 变化 / 环比%），下面还有「每一期 × 全部字段」的完整明细（可切到环比视图、可下载 CSV）。
- 逐月时，已经过完的月份如果达人组上传了「月数据」Excel（目前 Creators 有 6、7、8 月），直接用它，所以 6→7→8 月的环比是完整的。
- 自选区间：选一段日期，自动跟紧挨着它、同样天数的前一段比。
- 周 / 月默认按日均比（各期天数不同），自选区间默认按合计比；比率类（CTR、完播率…）按曝光 / 播放 / 观众加权重算，不是简单平均。

「两段对比·归因」和「达人 / 内容排行」也一样：选了本期，基期自动 = 本期前面同样天数的一段（可以关掉自动、手动选）。

**达人数据怎么"照搬"运营的分析**
- 链接 = 达人组 Products 表的 Product ID（跟运营是同一批链接、同一个名字），逐链逐日的达人 GMV 跟运营日报「达人渠道 GMV」99.6% 一致。
- 漏斗一样：GMV = 曝光 × CTR × CTOR × 客单价（达人侧 CTOR = 订单 ÷ 点击）。
- 渠道 = 达人视频 / 达人直播 / 商品卡及其他。按链接拆的视频/直播 GMV 用运营日报里的精确值（没载入运营日报时用挂车关系估算，页面会标注）。
- 运营没有、达人独有的维度也放进了归因：**按达人拆**（Creators 表，精确）、**按视频/直播拆**（每条内容精确）、**这条链是哪些达人在推**（挂车关系，近似：视频带来的成交里买家可能买了别的链接）。
- 「前端 / 后端」页除了按链接的字段，还能看达人表 / 视频表 / 直播表每一个原始字段的每日合计（完播率、互动率、观看时长这类按播放/观众加权）。

**运营页里自动附「达人侧原因」**（两边数据都拉了才会出现）：两段对比、异常预警、链接下钻、日环比 & 回暖里，只要某条链的变化主要在「达人」渠道，就列出这条链在达人组数据里的原因——达人侧曝光（视频挂车 / 直播挂车）每天怎么变的、新发视频 / 发布达人 / 出单达人、曝光掉得最多或涨得最多的挂车达人。「两段对比」最下面还有一块达人侧同期对照（先比曝光，再比 GMV）。达人组数据比运营日报更新慢，所选时间段没被达人数据覆盖一半以上时会直接说明，不下结论。

配色主题在 `.streamlit/config.toml`（深色系 + 品牌粉红色 `#C2416B` 强调色，跟图表里"达人"渠道的颜色是同一个色，界面和图表统一视觉）。想换颜色就改这个文件的 `primaryColor` 等几行，不用碰代码。
